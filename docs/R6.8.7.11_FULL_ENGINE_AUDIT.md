## R6.8.7.11 R3 — Live-log audit and runtime hardening — 2026-09-30

### Observed production/Demo symptom

The supplied Bybit Demo logs showed repeated:

`Execution cycle error 1/3: float() argument must be a string or a real number, not 'NoneType'`

The error appeared in more than one profile. BOT-02 progressed far enough to produce the ENTRY PIPELINE diagnostic before the cycle error, while the other supplied profiles could fail earlier. The previous worker exception handler logged only the exception string, so the exact call site was not available in the log.

### Root-cause class fixed

The execution worker contained a large settings-ingestion boundary with direct `float(...)`, `int(...)`, Boolean and `.strip()` reads from the GUI snapshot. A transient `None`/blank snapshot value could therefore abort the entire cycle before the normal strategy diagnostics completed.

R3 adds:

- `_safe_runtime_float()`
- `_safe_runtime_int()`
- `_safe_runtime_bool()`
- `_safe_runtime_text()`

These helpers preserve declared defaults for transient invalid snapshot values. Boolean handling is especially important: `bool(None)` would otherwise become `False`, which could accidentally disable a safety switch.

The cycle error handler now also records the final traceback lines under `CYCLE ERROR TRACE:`, so any future non-exchange exception is diagnosable from the live log.

### Configuration / callback audit

The R6.8.7.11 profile-persistent 2F controls were already correctly present in preset mapping, GUI creation, save/load and migration. R3 found one runtime propagation gap: the live AI trade-management call received the 2F enable flag but not all persisted 2F threshold/requirement values. R3 now passes:

The live decision, shadow, pipeline and trade-management paths therefore use the same profile-controlled 2F contract.

Duplicate identical 2F preset keys were removed so the Python dictionary has one authoritative value per field.
