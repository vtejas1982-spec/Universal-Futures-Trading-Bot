## Findings

### Fixed — AI trailing stop was not called

The live engine contained `_manage_ai_trailing_stop()` but no runtime invocation. That meant the documented post-TP1 ATR trailing feature never activated.

R6.8.7.2 invokes it after TP1/break-even processing while the position is live.

### Fixed — post-fill execution safety gap

The pre-entry spread/slippage/depth/drift gate is only a snapshot. A market order can fill after the order book moves.

R6.8.7.2 compares the actual exchange-reported average entry against the pre-entry executable bid/ask. If actual fill slippage exceeds the configured slippage envelope, the trade is rejected before protection installation and the existing fail-closed recovery flattens it.

### Verified — SL/TP resolver

- One SL basis is selected.
- ATR has priority over ROI/fallback in normal protection.
- TP targets use the resolved stop distance when ATR TP is active.
- TP2 must be farther from entry than TP1.
- LONG/SHORT price ordering is checked.
- Liquidation-safe stop distance is checked before an order can be considered protected.
- Actual fill price and actual position quantity are used.

### Verified — TP quantities

- Percent mode requires TP1 + TP2 = 100%.
- Fixed quantity mode requires the quantities to match the actual position contract.
- SL covers 100% of the live position.
- Tiny positions that cannot be split are rejected before entry.

### Verified — risk sizing

- Equity risk uses `risk_pct / 100`.
- Position size is based on the resolved stop distance.
- Notional is capped at 95% of balance × leverage.
- AI dynamic risk cannot exceed configured Risk Per Trade.
- Leverage tiers can only reduce risk / increase cooldown.
