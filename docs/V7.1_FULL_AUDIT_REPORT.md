## V7.1 changes
### Scanner ephemeral lifecycle
- Temporary `SCANNER-*` preflight profiles are marked `PREFLIGHT_WORKER`.
- Rejected/failed preflight directories are purged only after safe terminal conditions are verified.
- Active/recovery profiles are protected from deletion.
- Startup reconciliation purges abandoned preflight-worker directories.
- Purge failures are deferred and logged rather than treated as safe-to-delete.

### Completed Trade History
- Hub `TRADE HISTORY` tab shows completed trades only (`ended_at IS NOT NULL` and `result <> 'OPEN'`).
- Filter by normal BOT profile or `ALL`.
- Scanner children are attributed to their parent `BOT-*` profile while retaining the full scanner engine ID.
- History includes entry/exit times, price, quantity, P&L, result, exit reason, duration, leverage and trade ID.
- History includes entry, SL, TP1, TP2, BE and final exit order IDs plus TP1/TP2 fill quantities/prices/times.
- `COPY SELECTED` copies the complete selected record.
- History refreshes periodically from authoritative SQLite storage.

### Final order-ID telemetry repair
The initial V7.1 history implementation created the trade row at entry, before protection orders were installed. The final V7.1 repair now synchronizes the real exchange SL/TP1/TP2 IDs immediately after protection verification and updates TP2 ID if TP2 is explicitly recreated.

The original SL ID is retained separately from the BE order ID. BE no longer overwrites `active_trade['sl_order_id']`.

## Safety contracts retained
- AI/evidence gates unchanged.
- Saved profile remains authoritative; no silent preset replacement.
- No leverage/risk/quantity gate loosened.
- Execution-quality gates retained.
- Cost/liquidation gates retained.
- Symbol ownership and existing-position fail-closed behavior retained.
- Scanner remains discovery/preflight authority; actual orders remain delegated to normal child trade engines.
- TP1/TP2 remain reduce-only and protected.
- TP1 fill confirmation remains exchange-based.
- True BE uses the actual filled exchange entry.
- TP2 is preserved after TP1 and recreated only on explicit exchange cancellation/rejection/expiry.
- Linux memory floor 180 MB, recovery 240 MB, RSS ceiling 780 MB retained.
- Windows resource governor and async external preflight retained.
