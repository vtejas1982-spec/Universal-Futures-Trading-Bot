## Fixed
- Scanner preflight workers no longer leave every rejected temporary `SCANNER-*` profile directory behind.
- Startup reconciliation removes abandoned `PREFLIGHT_WORKER` directories when they are safe to delete.
- Active-trade and recovery profiles remain protected from automatic deletion.
- Hub-owned cleanup paths are fail-closed and log deferred purges rather than deleting uncertain state.

## Added
### Completed Trade History
A new Hub `TRADE HISTORY` tab displays completed trades only.

The history can be filtered by normal BOT profile or `ALL` and includes:
- result: WIN / LOSS / BREAKEVEN
- parent BOT profile
- full scanner engine ID
- symbol and side
- entry/exit timestamps
- entry/exit prices
- entry quantity and final exit quantity
- realized P&L
- exit reason
- leverage
- duration
- trade ID
- entry order ID
- original exchange SL order ID
- TP1 order ID
- TP2 order ID
- BE order ID
- final exit order ID
- TP1 fill quantity/price/time
- TP2 fill quantity/price/time

Scanner children are attributed to their parent BOT for easy filtering, while the actual engine ID remains visible for forensic tracing.

### Order-ID telemetry repair
The trade record is created when the actual position opens, before protection orders are installed. V7.1 now updates the authoritative SQLite row immediately after SL/TP1/TP2 verification so the history contains the actual exchange order IDs.

When TP2 is explicitly recreated, its new order ID is synchronized to the trade record.

The original SL ID and BE ID are stored separately; a BE order no longer overwrites the original SL order ID in history.

### History operations
- `REFRESH`
- `COPY SELECTED`
- `ALL PROFILES`
- periodic lightweight refresh from the master SQLite database
